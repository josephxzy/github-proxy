# 双层限速设计

## 背景

代理需要同时满足两个需求：限制单个用户的下载带宽（防止单用户占满带宽），以及限制所有未认证用户的总带宽（防止多人同时下载耗尽服务器资源）。单一的限速器无法同时满足这两个维度。

## 决策

**双层限速：单流漏桶 + global 共享令牌桶**。每个下载请求有独立的单流漏桶（限制峰值带宽），所有请求竞争同一个全局令牌桶（限制总带宽）。两者串联，白名单用户跳过所有限速。

## 当前规则

- `rateLimitedWriter.Write()` 对每次写入依次过两道限速：先单流漏桶，再 global 令牌桶。
- 单流漏桶没有空闲重置逻辑——暂停再久，恢复后只允许 32KB 突发，后续严格按 rate 限速。
- 单流漏桶按请求独立创建（每连接一个），同名用户 N 个并发下载获得 N 倍带宽。
- 全局令牌桶提供真正的跨用户总带宽上限。
- 白名单 token 用户跳过所有限速器，直接透传写入。
- 配置：`DOWNLOAD_RATE`（单流）、`GLOBAL_RATE`（全局），0 = 不限。

## 示例

**推荐做法**：
- 单流限速 `DOWNLOAD_RATE=5242880`（5MB/s），全局 `GLOBAL_RATE=52428800`（50MB/s）
- 白名单 token 实现免限速下载

**禁止做法**：
- 删除单流限速只保留 global（会导致单用户带宽波动）
- 在单流漏桶中添加空闲重置逻辑（会导致暂停后数据涌出）
- 用 global 令牌桶替代单流漏桶（粒度不够）

## 失败模式

| 症状 | 原因 | 排查 |
|:---|:---|:---|
| 下载速度远低于配置值 | global 令牌桶被多个用户打满 | 检查并发连接数，调大 `GLOBAL_RATE` |
| 暂停后恢复瞬间速度飙升 | 漏桶有空闲重置逻辑 | 确认 `nextTime` 不重置 |
| 全局带宽超标 | global 令牌桶未正确共享 | 确认 global 限速器是全局单例 |
| 白名单用户仍被限速 | 白名单检查未生效 | 检查 token 是否正确匹配 |
